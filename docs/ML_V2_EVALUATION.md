## 9. Threshold Analysis
Current baseline engine uses 0.39 and 0.69.
Based on predicting the holdout set:
- **Threshold 0.20**: FPR 5%, FNR 0% (Strict security, higher human friction)
- **Threshold 0.39**: FPR 1%, FNR 0% (Good balance)
- **Threshold 0.70**: FPR 1%, FNR 1% (Relaxed security, bot leakage begins)

**Recommendation**: The current `0.39` (Allow/Captcha boundary) and `0.69` (Captcha/Block boundary) are surprisingly optimal for this dataset. Keep them.

## 10. Calibration
Because this is synthetic data generated by 8 deterministic rules, the Random Forest leaf nodes are incredibly pure. The predicted probabilities tend to cluster near 0.0 or 1.0 rather than smooth continuous risks. Proper Platt scaling or Isotonic Regression calibration should only be performed once we acquire real NVAS telemetry.

## 11. Limitations
**Is Dataset V2 realistic enough to claim production-quality ML performance?**
**NO.** 
While we fixed the 1-dimensional trivial overlap (e.g., speed ranges), this is still a *synthetic/literature-informed benchmark*. 
Because the bots were generated by 8 discrete Python rules (e.g., `if bot == 'no_mouse': speed = 0`), the Random Forest easily reverse-engineered those 8 rules (e.g., `if speed == 0 -> bot`). Real-world bots evolve dynamically and humans behave chaotically.
